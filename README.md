## 项目定位

亿企工场 TMS 是亿企工场的运输管理业务应用，面向物流运输从主数据、订单和运单生成，到配载、在途、签收与财务协作的完整履约过程。

本仓只维护 TMS 页面、业务 API、领域类型、运输规则与专属 Edge Functions。认证、租户、菜单、权限、布局、路由、公共组件、Store 和 Supabase 公共客户端由 [`art-supabase-pro`](https://gitee.com/art-si/art-supabase-pro) 统一提供。

## 标准履约链路

```text
客户委托
  → 开单 / AI 识别
  → 订单与运单
  → 运力规划与配载
  → 装货 / 发车 / 在途
  → 到达 / 卸货 / 签收
  → 回单 / 费用 / 对账与利润
```

AI 智能填单只生成可复核草稿；调度推荐和异常研判只提供辅助判断。保存、改派、签收、费用与状态变化仍由有权限的操作人员确认，并由服务端业务规则约束。

### 调度运单编号

- 普通配载沿用原始运单号；拆单按原始运单号依次生成 `-01` 至 `-99`；合单使用独立的 `DY` 调度号。
- 拆单序号按同一原始单的历史调度记录递增，已撤销的序号不复用。撤销的普通配载记录保留审计历史，当前有效调度号仍保持唯一。
- 编号由数据库 `tms_create_dispatch_plan_secure` 在锁定原始单后生成。2026-09-28 已将两条待接单的历史拆单号修正为 `YD202608-013-01`、`YD202608-013-02`；回滚验证、实际结果校验和有效运单号唯一性校验均通过。

### 运输订单报价

- 订单列表的“报价”操作打开报价表单。运输费、卸货费、送货费、保险费、税费与补充费用共同组成报价总额；从 `tmsOrderQuoteExpenseItem` 字典选中费用项后立即添加，可连续添加多项，当前字典为人工费、吊车费、其他费用。
- “保存报价”保留草稿；“提交报价”仅在系统内标记为已提交，不发送客户通知。报价独立存于 `public.tms_order_quote`，不改写订单应收费用；每单保留一份当前报价。附件最多 6 个，必须属于订单租户。
- 读写分别经 `tms_get_order_quote_secure`、`tms_save_order_quote_secure` RPC；菜单权限 `TmsOrderList:Quote`、订单字段权限、租户范围、金额与字典值由服务端复核。2026-09-28 使用事务回滚验证了同租户草稿与提交、金额合计、零额提交拒绝及平台全量、平台选定租户、普通用户的跨租户访问边界。

### 承运商多选资料

- `public.mdm_carrier.carrier_types` 和 `dispatch_channels` 保存承运商支持的全部类型和调度渠道；原有 `carrier_type` 和 `dispatch_channel` 保留首选值，供旧接口继续读取。数据库触发器维护两种表示的一致性，数组不允许为空或重复，渠道仅接受 `online`、`offline`。
- 新增和编辑通过 `tms_create_carrier_multi_secure`、`tms_update_carrier_multi_secure` 写入；原有安全 RPC 仍负责租户、业务操作及字段权限校验。列表类型筛选匹配数组内任一类型，导入支持多值，调度参选和详情回显全部渠道。
- 2026-10-18 已回填现有 3 条记录；以已有承运商的创建者身份调用安全更新 RPC，并用事务回滚验证了双类型、双渠道写入及首选值同步，回滚后原数据保持单值。模块边界、UI、类型、Lint、样式和 71 项单元测试通过。

### 基础资料补充

- “黑名单”“投诉咨询”“电子合同”“运输协议”分别存于 `tms_driver_blacklist`、`tms_service_case`、`tms_electronic_contract`、`tms_transport_agreement`。四页复用平台的查询表格、详情描述、上传控件与空状态组件。
- 服务单号、电子合同号、运输协议号通过系统编号规则按租户和月份生成，分别使用 `TS`、`DZHT`、`YSXY` 前缀与 3 位流水码。复制合同会生成新合同号，终止合同保留原记录。
- 普通用户只可读取所属租户的资料；四表各有一条按租户范围读取策略和三条平台超级管理员写入策略。新增、编辑、删除、复制及终止操作由数据库边界约束。承运商和车辆参选按租户筛选，运输协议保存车辆档案中的车型与车长快照。
- 合同复制与承运商参选 RPC 供已登录用户调用，函数内再次检查权限和租户范围；复制还检查平台超级管理员身份，普通用户的承运商参选结果不含联系人或法定代表人。
- 2026-09-29 为四页各创建 2 条演示记录，并以事务回滚验证了新增、编辑、批量删除、合同复制与终止、编号生成及跨租户读写边界。数据库性能顾问对四张新表无提示；安全顾问对上述两个已登录用户可调用的受控 RPC 仍给出常规 [`SECURITY DEFINER` 提示](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)。

## 独立运行

环境要求：Node.js `>= 22.0.0`、pnpm `>= 11.9.0`。

```powershell
pnpm install
pnpm dev
```

默认访问 `http://localhost:3016`。使用在途地图时还需配置高德地图浏览器 Key、安全码和允许域名。

```powershell
pnpm check
pnpm build
pnpm preview
```

生产构建输出到 `docs/`，默认公共路径为 `/art-supabase-tms/`，可作为 Pages 发布目录。

## 与主仓协作

TMS 业务修改在本仓提交并推送，随后在主仓更新 `modules/art-supabase-tms` 子模块指针。数据库菜单继续使用稳定的 `/tms/...` 路由前缀；跨模块读取通过租户隔离、字段最小化的 API/RPC 契约完成，本仓不直接导入其他业务仓源码。

## 安全原则

- 前端菜单和按钮只改善交互，RLS、RPC 与 Edge Functions 才是最终授权边界。
- 普通用户只使用租户范围内的安全数据；受控写入和状态变化必须经过服务端校验。
- 前端只配置 Supabase `anon` / publishable key，服务端密钥不得进入 Vite 环境变量。

## 经营决策与运营管理报表

两个目录、十五个叶菜单使用路由与组件路径一致的独立入口，位于 `src/views/business-decision/**` 和 `src/views/operations-analysis/**`。页面权限由后端菜单控制；只读查询不新增业务写入动作。

### 页面职责

每个 `index.vue` 自己组合头部、指标、图表和台账，声明该页的列、跳转与统计说明。月度经营、各维度毛利分析使用金额对比图；应收、风险和运营过程台账以明细为主；运营 KPI 按六项目标列示实际值、完成率和预警。十五页都有可查询明细，但图表和业务指标按用途选择。

共享目录 `src/views/components/management-reports` 的职责限于：

- `workspace.vue`：页面布局与项目头部，无报表类型判断。
- `use-report-query.ts`：日期与关键词、分页请求、加载/错误状态、租户和路由查询变化。另保留最近一次成功查询的只读条件，六个经营分析页穿透使用该条件，未提交的输入不能改变已显示数据的下钻范围。浏览器覆盖未提交关键词、未提交日期及月度→客户→订单→车辆链路；完整回归 25 项通过，修正双请求加载测试后剩余 1 项复测通过。
- `report-trend.vue`、`comparison-chart.vue`：已准备好的图表标签、系列、单位和刻度，不判断页面业务。
- `report-cells.ts`：数字、利润结果、回单状态和受路由可用性约束的链接；不根据报表类型分支。
- `financial-comparison.ts`、`report-metrics.ts`：已归集收入成本比较及财务指标展示口径。
- `catalog.ts`：仅保留路由身份清单，无列、数据转换或页面业务逻辑。

金额对比图逐项保留可读数值：营收存在而成本未知时仍绘制营收，成本留空并提示未知/权限限制，不能把 `null` 转成零。两项均不可读的对象不绘制；全部不可读时显示空态。浏览器回归覆盖部分金额未知、全部未知，以及紧凑布局的表格可视高度。

### 数据与安全边界

入口 `public.tms_management_report(text,date,date,text,integer,integer)` 校验登录与精确报表权限。运营数据由私有只读查询 `app_private.tms_operational_report_rows` 按订单、车辆、司机和承运商各自粒度组织；私有函数不向 PUBLIC/anon/authenticated 授权。每个查询保持租户范围，普通用户伪造租户头不能改变结果。

金额先经过既有运单利润、客户对账单字段权限投影；任一必需金额不可读时不返回可倒推的汇总。财务按订单开单日期，收入按订单去重、已审核运单费用合并。多执行运单且无明确收入分摊时，单车/司机收入与毛利待核算。按执行运单关联车辆和司机，筛选在去重计算之后进行。查询跨度不超过一年，单页不超过 200 行，汇总与图表在分页之前计算。

月度总览按全部未取消订单统计运量（吨）与方量（m³），读取订单安全字段投影，重量由千克换算为吨，同一订单只计一次。未关联有效主运单的订单也纳入月度、客户、线路和订单报表，月度另列待归集订单数；此类订单成本、毛利及受影响的汇总保留待核算，不当作零成本盈利。现有八笔验收订单合计 80 吨、160 m³，SQL 回归校验该合计及完整订单计数。

单车盈亏另列已归集油费、路费，分别取已审核的 `fuel` / `toll` 运单费用，沿用费用明细安全投影并受汇总金额权限约束；查询日期、关键词和执行车辆与主表一致。零表示所选范围没有已审核的该类费用，不代表没有实际开支。充电、燃气等不混入油费，维修、工资、保险折旧仍需完整分摊。SQL 回归按原始已审核费用校验两项合计。

车辆调度是一车一行的当前快照，不因日期筛选隐藏档案；司机台账一名司机一行，任务、执行里程、考勤和事故使用明确关联。订单在途和回单以订单开单日期筛选；承运商按运单创建日期。回单合并订单、运单及签收记录凭证；上传不代表审核通过。异常覆盖回单异常工单及超期未签收提示，自动提示不视为已登记结案业务。

### 明确保留的业务缺口

当前毛利是已归集口径，不是完整车辆/司机净利润。月度总览已接入本年累计营收、已归集成本和毛利；预算对比、工资/折旧/保险的完整分摊仍未接入。应收已接入运输暂估下推的已审核财务应收、开票、收款/退款及其他核销；催收台账与风险分级尚未接入。经营风险已汇总车辆事故、违章与运输财务应收逾期，货损理赔尚未合并。

经营风险中的事故、违章按发生日期读取，沿用 `vehicle_accident_to_secure_json` / `vehicle_violation_to_secure_json` 的司机、描述与金额字段权限。已登记风险金额取事故公司承担金额或违章罚款，不等同于预计损失；没有明确来源的订单、客户及风险分级保留未知。风险首页按事项计数，不再使用签收、回单等履约指标。现有事故记录已通过源记录数量与安全投影一致性回归。已为原验收车辆创建两条带 `[TMS报表验收20261024]` 标识的违章测试记录，金额分别 100 / 200 元、状态分别未处理 / 已处理；均声明不代表真实交通违法。风险查询验证总额 300 元、无猜测订单归属及普通用户伪造租户头不改变结果，真实页面两条记录已视觉核对。

运营 KPI 已列六项目标；装载率采用运单重量/对应额定载重，准点率采用已到货且计划时间完整订单，回单及时率采用签收后 7 天内回收。尚缺重空驶里程、统一核损、期初期末应收余额及赊销收入，三项实际值保留待核算。位置、预计回场、维修计划、司机违章唯一关联、货损理赔和缺失原因等没有可靠来源的字段不补零或编造结论。

### 验证与证据范围
